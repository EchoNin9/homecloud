## Design notes worth knowing

Everything in `docs/20261025resume.md` "Design notes" still holds, plus the notes below.

**UI**
- The owner prefers confident visuals (colour, depth, a brand mark) over minimal ones. They've picked
  the bolder option in side-by-side reviews twice.
- **Colour meaning:** teal (`--hc-accent`) is the brand and interactive accent. Amber (`--hc-on`) only ever
  means "on". Red means alert. Keep it that way; the update badges use teal for this reason.
- **Theme:** `src/theme.ts` sets `<html data-theme="light|dark">`. `app.css` and the dashboard's dark tokens
  key off that attribute, not `@media (prefers-color-scheme)`. The dashboard calls `initTheme()` itself
  (idempotent), so embedding hosts still get dark mode.
- **Light colour:** helpers are in `components/color.ts`. It has no imports so `web/mock` can use it.
  HA's `rgb_color` reflects the output in every colour mode, which is why the tile tint uses it.

**Cognito branding** (`modules/homecloud/cognito.tf`)
- Logos must be between 1:1 and 4:1 width:height. Colours are `RRGGBBff` without `#`.
- AWS publishes no settings schema. Unknown keys are ignored, but bad values fail at apply.
- The domain `depends_on` the style. A failed branding apply leaves the classic sign-in working, which
  is what happened in the two failed deploys on 2026-10-25.
- The local AWS CLI (2.9.x) predates the managed-login commands. Use `tofu state show` to inspect.

**Ops**
- The NAS compose stack folder is `/volume1/docker/homecloud/stack`, not `/volume1/docker/homecloud`.
  Run the docker CLI as `sudo /usr/local/bin/docker`.
- CI's `cloud` job sometimes times out reaching `registry.opentofu.org`. Re-run the failed job; it isn't
  the change.
- Deploys use the OIDC role (`vars.AWS_DEPLOY_ROLE_ARN`), not access keys. `deploy.yml` refuses plans that
  delete or replace the IoT certificate, the DynamoDB table or the user pool.
