## What is running

**AWS (standalone example, `us-east-1`)** — `cloud/terraform/examples/standalone`, applied with
**OpenTofu** (`tofu`, 1.12; repo requires >= 1.10). The local `terraform` is 1.5.7, too old.
AWS profile: `echo9` (static keys; `echo9-sso` also exists, SSO login needed).

```sh
cd cloud/terraform/examples/standalone
export AWS_PROFILE=echo9 AWS_REGION=us-east-1
tofu output                      # api_url, iot_endpoint, web_url, web_bucket, user_pool_id, ...
```

- 45 resources: Cognito pool + client + hosted UI domain, API GW + 2 Lambdas, DynamoDB
  `homecloud-state`, IoT thing `homecloud-home`, S3 + CloudFront.
- One home: `home_ids = ["home"]`. Device cert was made from a local CSR (key never in state);
  `terraform.tfvars` holds the CSR. `certs/` (cert, key, root CA) is local only, gitignored.
- State is in S3 bucket `homecloud-tofu` (us-east-1), managed by `cloud/terraform/bootstrap`
  (created by hand, imported 2026-10-21 with a gitignored `terraform.tfvars`:
  `bucket_name = "homecloud-tofu"`). Versioned, SSE-S3, TLS-only policy, old versions expire
  after 90 days, S3 native locking.
  - `homecloud/bootstrap.tfstate`: bootstrap stack (gitignored `backend_override.tf` +
    `-backend-config` flags, per `docs/first-deploy.md` step 1).
  - `homecloud/standalone.tfstate`: the deployment. Gitignored `backend.hcl` next to `main.tf`,
    then `tofu init -backend-config=backend.hcl`:

  ```hcl
  bucket       = "homecloud-tofu"
  key          = "homecloud/standalone.tfstate"
  region       = "us-east-1"
  encrypt      = true
  use_lockfile = true
  ```
  (Moved from `standalone/terraform.tfstate` on 2026-10-21; old key deleted, recoverable from S3
  versions.)
  Older state versions can be restored from S3 object versions if a bad apply corrupts it.
- Cognito user: the owner's email, in group `admin`. "Forgot password?" works once the
  first login (temporary password) has been completed.
- Web UI built from `web/` and synced to `web_bucket` (excluding `config.json`, which Terraform owns).

**NAS: Synology DS1819+ ("NAS2"), DSM 7.4.1, x86_64, Container Manager (compose v2.20)**

- SSH: `ssh -i ~/.ssh/nas2 -o IdentitiesOnly=yes admin@<nas2-ip>`. `admin` has passwordless sudo

  HA long-lived token.
- One-time setup script: `stack/scripts/nas-setup.sh` (cert perms, mosquitto passwd, starts HA +
  mosquitto). Source: `nas/scripts/nas-setup.sh`.
- Containers up: `homecloud-homeassistant-1` (:8123, host net), `homecloud-mosquitto-1`
  (127.0.0.1:1883, auth), `homecloud-bridge-1`.
- Verified: bridge connects to HA and IoT Core and sends a snapshot (77 entities). DynamoDB `META`
  shows `online: true`.

## Gotchas found (already fixed/documented)

- DSM's kernel lacks seccomp, so BuildKit builds fail. Build the bridge with
  `sudo DOCKER_BUILDKIT=0 docker build -t homecloud-bridge:0.1.0 bridge`, then
  `docker compose up -d --no-build bridge` (see `docs/synology.md`).
- The ingest Lambda dropped `status` messages (no `v` field per contract). Fixed in `6b56491`.
- The `!` prefix in Claude Code has no TTY, so `sudo` password prompts over ssh fail there.
