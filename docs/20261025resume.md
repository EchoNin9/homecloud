## Design notes worth knowing

- History days split at local midnight for a fixed `history_utc_offset_hours` (-7 here; Vancouver is
  permanently UTC-7, no DST). Rollups re-roll the last 3 days each night, so they are idempotent and
  heal a missed run. `history_entities` globs (module variable) decide what is tracked.
- The web client fills a quiet raw window from the entity's current state. So a stable sensor shows a
  flat line, not "no history". Every no-data path in `web/src/components/history.ts` returns
  `{ kind: 'empty' }`, and `history.test.ts` pins those cases.
- `monitor` states are set through HA's REST API. They vanish on an HA restart for up to 60 s.
- UI follows Home Assistant: the per-tile star/history buttons moved into the more-info dialog; views
  (By type, By area, Recently changed, My groups) live in the sidebar, which also jumps to sections.
  Icons are `@mdi/js` (HA's set, tree-shaken); `components/icons.tsx` maps domains/device classes to them.
- Sun & moon card (sun.sun more-info, also from the sunrise/sunset badges): today's altitude of both,
  computed in the browser from the home location the bridge adds to sun.sun (`components/astro.ts`,
  tested against 2026 eclipses and Vancouver rise/set). HA has no moon-position entity.
- Groups: hand-picked ids (`groups`) plus an optional live search (`groupQueries`), minus ones removed by
  hand (`groupOut`); all browser-local prefs. `util.ts` `groupIds` / `setMembers` / `moveGroup` are the only
  way to read or change membership (tested).
- Custom domain: CloudFront only takes the domain once ACM says ISSUED (`web_cert_arn` in `web.tf`), so an
  external-DNS setup never breaks the site between the two applies.
- WUD 9 refuses to start without `WUD_AUTH_ADMIN_*`, even with its server disabled.
